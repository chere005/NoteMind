## Method and boundaries

I independently inventoried the Main, renderer, persistence, pen/helper, import/export and feature entry points before using earlier reports as context. I followed file identity, captured initiating owners, accepted work, publication receipts, retained assets and final cleanup across those boundaries. Findings were confirmed with a failing test of the actual handler/class where possible, then fixed in explicitly granted files and checked with affected existing tests. Tests use actual temporary files, actual archive workers or actual process failure where stated; injected scheduling/fault seams are distinguished below.

All development checks used the pinned stable-candidate Electron executable as Node with `ELECTRON_RUN_AS_NODE=1` and its node_modules through `NODE_PATH`. No installed app, user profile, physical pen/camera, clipboard, screen, browser, native build, package, release, push or full repository test suite was used by this auditor. Generated renderer/pen bundles remain Root's build responsibility.

Project rename and Markdown move preserve foreign files at the tested preparation/publication/rollback seams; project target creation is deliberately exclusive. It is not a durable transaction coordinating arbitrary external writers: a process crash between preparing a target and unlinking the source can leave both names, and checks cannot atomically lock another program's write between the last asynchronous check and an OS call. It does not claim an all-filesystem power-loss proof. Unsupported-hardlink behavior was injected on actual temporary files, not exercised on a physical external filesystem.

The actual helper spawn failure, archive/file work and injected event boundaries do not substitute for native pen, hidden browser, frozen corpus, final package fidelity, memory/OCR gates, OS/platform breadth or full preflight. Root's measured pipeline failures remain Root's active work and are not claimed fixed by this report.
