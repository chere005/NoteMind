# Active source editor: architecture and bounded prototype handoff

Read-only production review began at Root `398c6d55` on November 18, 2026. The test-only primitive trials below used Root-granted serial native lanes. This note does not introduce an App editor, a production dependency or release qualification. Root is retaining the production editor while the large-source requirement remains open.

## Confirmed failure and what a fix must change

The exact16,777,216-byte SHA f50aa3d715f86ee06444e5a7a004e19b45f229f377c18994a6d6b7fe2853cf1f is one long styled Markdown line. Existing cold native source-control evidence crosses the unchanged1GiB aggregate guard after assigning the entire native textarea value, before any counter executes. Inactive editor retirement removes separate duplicated representations but cannot close this cold workload. Fonts, wrapping, input, admission and guards remain authoritative.

A fix needs a complete canonical source model with a bounded editable view, including bounded fragments within a single wrapped line. A full-size textarea hidden behind a custom view retains the failed representation. Returning only visible text from source.value would corrupt full offsets and saves. Changing wrapping or lowering input limits would not fix the required workload.

## Proposed interface and ownership

Introduce an explicit NoteMindSourceEditor service, separate from a DOM element. Do not monkeypatch HTMLTextAreaElement value, selection or methods. It owns an immutable full source model, revision, UTF16 selection anchor/head/direction, composition state and a viewport host. Minimal operations: read snapshot/text/slice; replace(from,to,text,selectionMode,origin); setSelection; focus/containsFocus; scrollToPosition/captureAnchor/restoreAnchor; begin/end atomic transaction; subscribe to accepted edits/selection; attach/detach/dispose. All four existing setRangeText modes (select/start/end/preserve) need exact clipping/mapping semantics. UTF8 admission remains the App50MiB authority, not the Word16MiB default; it must not be approximated by UTF16 length.

Capture tab, exact document identity, revision and origin at each operation. A late import, save or async field action either updates that owner or rejects after it closes; it cannot target whichever editor is now active. Maintain one current mounted view; per-note canonical/selection/scroll records survive view retirement. Composition-owned DOM must not be destroyed during an active IME transaction without a defined commit/cancel transition. Programmatic edits during composition, tab switch, close and mode switch require explicit ordering and tests.

Keep NoteMindHistory as the only cross-feature Undo/Redo authority: an independent CodeMirror history stack would omit asset/metadata transactions and diverge after image/PDF import. A transaction adapter must feed actual trusted input provenance and composition grouping into the existing authority. Unknown/programmatic edits should take the conservative full-history path. For sustained large-source typing, storing a fresh full serialized string on every keystroke remains a separate allocation risk; a model snapshot/changed-range history bridge needs measurement and correct sharing/accounting, not an unmeasured claim that viewport virtualization alone makes typing bounded.

Materialize complete strings only at explicit existing compatibility/persistence/count boundaries with revision-cached ownership; never save only rendered fragments. Audit every direct source access before enabling an alternative backend. Existing synchronous APIs can be migrated in coherent groups, while the production default remains unchanged until the complete adapter is green. Editor line ending policy must be explicit: CodeMirror defaults can split/normalize CRLF; exact canonical text, trailing newline, surrogate, combining and bidi behavior must be verified rather than assumed. The prototype sets lineSeparator to LF explicitly; no general EOL parity claim follows.

## Dependency order and acceptance

1. Prove bounded cold layout for the unchanged exact single-line16MiB source before any product integration. Current candidates fail this gate; use first-measure telemetry to identify the actual cause before changing a library or choosing another view. Preserve each failure and all source/process receipts.
2. Freeze the model/editor contract and use existing native textarea on ordinary small sources as the behavior oracle: all selection directions/modes, UTF16/Unicode/line endings, programmatic edits, fields/focus, context actions and composition. This is an interface migration, not a large-source performance claim.
3. Integrate the candidate view plus the canonical owner/input/history transaction bridge as one dependency. In parallel, separate owners can migrate formatting/structure/table consumers, Find/footer/scroll, and captured insertion/persistence. Merge one coherent group at a time; no alternative production default until no direct-access holes remain.
4. Run deterministic model/ownership failures and exact before/after serialization/history cases, then actual hidden native typing, IME route, backward selection, copy/cut/paste/select-all, far scrolling, Undo/Redo, mode/tab/close/reopen and asynchronous import completion. Physical hardware/assistive technology coverage must be stated truthfully; synthetic composition events are not real platform IME acceptance.
5. Repeat cold16MiB and App50MiB source authorities, giant single line/many lines/Unicode/tabs, exact original CSS/wrap/width/zoom, pressure/foreground save and all original guards. Full preflight, frozen package and real recovery/cancel gates follow integration. Measure serialization/history boundaries separately from view gains.

A complete production adapter and this qualification cannot honestly be promised by 8AM from the current unqualified primitive gates. The safe handoff is the complete consumer/ownership design, isolated exact-source failures and a causal next experiment; leave the production editor and admission limits unchanged until the dependent work is implemented and verified. The final UI report remains valid for its enumerated keyboard/PDF/menu fixes; it explicitly does not mark the active large-source or full100 mixed memory requirements closed.
