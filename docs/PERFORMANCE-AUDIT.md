## Filesystem durability portability

Writable temporary files are fsynced before publication on every platform. POSIX directory and verified read-only-object syncs remain strict: real open/stat/sync/close failures propagate. Windows explicitly reports those read-only/directory flush capabilities as unsupported, while still validating directory existence; it does not turn normal Windows saves into failures or recurring UI warnings. This preserves atomic publication and file-data sync without claiming a POSIX directory-durability guarantee on Windows. The compatibility branch has focused simulated-platform coverage; it is not a native Windows runtime test.

The distinction follows the actual [libuv 1.52.1 Windows implementation](https://github.com/libuv/libuv/blob/v1.52.1/src/win/fs.c): read-only open uses FILE_GENERIC_READ and fsync delegates to FlushFileBuffers, whose [documented contract requires GENERIC_WRITE](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers). It is an explicit platform capability decision, not a generic exception for EINVAL, EACCES or I/O faults.
