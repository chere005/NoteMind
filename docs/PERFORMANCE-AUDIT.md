## Filesystem durability portability

Writable temporary files are fsynced before publication on every platform. POSIX directory and verified read-only-object syncs remain strict: real open/stat/sync/close failures propagate. Windows explicitly reports those read-only/directory flush capabilities as unsupported, while still validating directory existence; it does not turn normal Windows saves into failures or recurring UI warnings. This preserves atomic publication and file-data sync without claiming a POSIX directory-durability guarantee on Windows. The compatibility branch has focused simulated-platform coverage; it is not a native Windows runtime test.

The distinction follows the actual [libuv 1.52.1 Windows implementation](https://github.com/libuv/libuv/blob/v1.52.1/src/win/fs.c): read-only open uses FILE_GENERIC_READ and fsync delegates to FlushFileBuffers, whose [documented contract requires GENERIC_WRITE](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers). It is an explicit platform capability decision, not a generic exception for EINVAL, EACCES or I/O faults.

## Managed-color fidelity finding (fixed; frozen repeat pending)

An independent hidden six-case oracle against writer `505fc94` compared default color-managed Chromium source pixels with actual PDF.js output pixels. Non-sRGB PNG gAMA 0.1 / 1.0 differed by up to 135 / 73 levels on an 8-bit channel; Display-P3 ICC PNG differed by 31; unprofiled CMYK JPEG by 32; CMYK with an installed generic ICC profile by 23. Display-P3 ICC RGB JPEG was the exact-zero control. These five confirmed export bugs were fixed by the managed-color source path; the expanded oracle then exposed cHRM without a transfer curve, fixed at `ef3397d` (integrated as `76c770c`).

The generated fixtures and exact expected/actual quadrants are saved at `raw-asset-cache/test-results/performance/scan-color-native.cjs` and `.json`. The installed CMYK profile was used only in an ephemeral JPEG and removed, with no profile binary committed. Two earlier harness API errors were corrected before the complete six-case run. This reciprocal author-stage oracle is separate from the still-pending fresh final review panels.

The final expanded 20-case source/copied-packaged-layout oracle matches all PDF and thumbnail channels exactly (0/255 maximum difference), including dark cHRM cases with and without gAMA. Both layouts execute real local qcms Wasm (4,063,232-byte memory), load its local resource successfully, and emit no warnings. JPEG DCT bytes remain exact. Combined owned-process peak is 884.39 MiB, Main plus worker threads 238.23 MiB; actual Main/archive-worker V8 limits are 4192/224 MiB. Artifact: `scan-asset-pdf/test-results/performance-0.37/scan-pdf/ef3397d-managed-color.json`. This covers these profiles/fixtures, not arbitrary ICC input; the final frozen application repeat remains required.
