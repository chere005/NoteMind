### Stored forms

- In memory use absence for Pen and integer tags 1 for Marker, 2 for Fountain Pen, and 3 for Highlighter. The existing width and pressure samples stay authoritative.
- In drawing JSON v1 use the optional fifth stroke tuple slot `[color,width,xy,pressuresOrNull,kind]`. Omit the slot for Pen. No JSON version bump.
- In the sheet store use a packed two-bit column indexed by stroke order after binary metadata, with zero for Pen. Typed chunks use `NMGFX3`. Raise head `formatVersion` to 3 on the first typed write while retaining existing checkpoint filenames. Ordinary-only chunks can remain `NMGFX2`.
- Binary drawing sidecars and PDF page ink use the same `NMGFX3` kind column. PDF binding and index stay at version 1. Camera uses the same binary chunk and store head versions. Legacy camera JSON uses optional `kind` on each stroke without a version change.

### Compatibility

The new app continues reading 0.39.0 stores and sidecars with absent kinds as plain ink, preserving their appearance and hashes. Existing pale highlights stay pale. 0.39.0 ignores the fifth JSON tuple slot and treats the stroke as ordinary ink. Saving it there drops the tag. Its binary reader rejects `NMGFX3` for editable ink and its version-2 store reader rejects the version-3 head. Large new binary sidecars can also exceed its generic asset limit.
